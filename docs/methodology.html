1. The scoring metric (exact re-derivation)

From the official problem page, "Performance metric". The leaderboard uses a distance-weighted Tversky index.

Predicted probability p(x)∈[0,1], ground truth g(x)∈{0,1}. Triangular kernel k(d)=max(1−d/R,0) with R=300 m (3 px at 100 m). With α=0.2 (false-positive penalty) and β=0.8 (false-negative penalty):

TP_w = Σ_g  max_{x:d(x,g)≤R} p(x)·k(d(x,g))
FP_w = Σ_{x:p(x)>0} p(x)·[1 − max_g k(d(x,g))]
FN_w = Σ_g [1 − max_{x:d(x,g)≤R} p(x)·k(d(x,g))]
DTI  = TP_w / (TP_w + 0.2·FP_w + 0.8·FN_w + ε)

Key consequences we engineer around: (i) a fault pixel is credited the best nearby prediction weighted by distance, so precise fault lines maximise TP; (ii) β=0.8 makes missing faults costly, but α=0.2 makes far-flung false positives cheap — so a focused, high-confidence lineament map beats a broad field. The metric is implemented independently in src/gemsdoe45/metric.py and passes a self-test against analytic cases (perfect map→1.0, empty→0.0, 1-px shift→0.667, all-ones→lower).

2. Candidate geological hypotheses (new, not yet tried)

All use only the 19 supplied feature bands — no external data — so the pipeline is reproducible without a DrivenData login. Ranked by expected DTI improvement vs implementation cost. Each is distinct from the prior GEMSDOE family, which used gravity/RTP-magnetic edge survival (WPH-01), radiometric K/Th, LiDAR scarplets, strain eigenvectors, or raw seismicity lineaments.

3. Validation pipeline

  • Metric self-test — metric.py verified against analytic ground-truth cases (PASS).
  • Format validation — validate_prediction_tiff checks shape, CRS, transform, dtype and the [0,1] range before any file is written (this is what eliminates the upload error).
  • Spatially-blocked proxy holdout — 4 contiguous quadrants, 300 m (3 px) guard from each split; the public fault catalogue stands in for ground truth. Reports per-fold and mean DTI.
  • Uniqueness audit — Pearson & Spearman correlation of the candidate against every prior GEMSDOE submission raster (sampled); must be |r| < 0.90 for both. Shipped candidate: max|Pearson|=0.10, max|Spearman|=0.10.

IRR-01 (flagged irregularity, carried over from the prior family and verified here): a sibling project measured the correlation between catalogue-holdout DTI and the live leaderboard at Spearman ρ≈0.09 (p≈0.80) — essentially zero. The proxy is therefore a relative ranking instrument, not a live-score predictor. For that reason we ship the most novel distinct hypothesis (H45-1a) rather than chasing the proxy maximum, and we are explicit that the live score is unknown.

5. Limitations & next steps (honest)

  • No live-score validation. The hidden test labels are not public; the proxy is the only internal instrument and is uncorrelated with live (IRR-01).
  • Fault-alignment gap. Our edge ensemble tops out near 0.07 proxy DTI on the catalogue; the strongest prior methods reach ≈0.18. Closing this (better lineament extraction / a learned ensemble) is the highest-leverage next step to raise the live score.
  • External data blocked here. Native radiometrics and a real seismicity catalogue would strengthen H45-3/H42-E but are unreachable from this sandbox (documented).
  • Recommended next sessions: (1) improve lineament extraction to raise catalogue-holdout DTI toward 0.18; (2) add the native GeoDAWN radiometrics once on an unrestricted machine; (3) re-run the uniqueness + proxy gates and ship an improved distinct candidate.
