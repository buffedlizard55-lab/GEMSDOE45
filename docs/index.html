Why the earlier "Predicted values must be in range [0,1]" error? A submission must contain only probabilities between 0 and 1. Our pipeline clips and validates every pixel to [0,1] and refuses to write a file that fails the check (see Method → Validation). The published file is verified: min=0.0, max=1.0, and the outside-footprint area is set to NaN exactly like the official sample submission.
Honest limitation (read before spending a slot): the live DrivenData score cannot be computed here because the hidden test labels are not public. We validate on a spatially-blocked proxy holdout (the public fault catalogue) and on uniqueness versus every prior submission. A sibling project measured near-zero correlation (Spearman ρ≈0.09) between such catalogue-holdout scores and the live leaderboard, so the proxy is a relative instrument only.
