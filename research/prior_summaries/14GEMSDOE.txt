The GEMS Prize (US DOE Office of Geothermal) pays for algorithms that surface
geological faults missing from the public USGS/INGENIOUS catalogue — faults that
indicate geothermal resources in the GeoDAWN region of Nevada and eastern California.
Score: a distance-weighted Tversky index that punishes missed faults
four times harder than false alarms. Fixed, and now covered by a test. What was wrong. docs/js/site.js assigned tifBytesNan without declaring it. The file is a strict-mode IIFE, so the
assignment threw ReferenceError: tifBytesNan is not defined inside the
promise chain; .catch() swallowed it and every download button stayed
disabled. The page reached FAILED: tifBytesNan is not defined and offered no
file — exactly the reported symptom. The Python suite could not see it, because nothing
in the suite executed the site's JavaScript. Reproduced, not guessed. node scripts/check_site_build.mjs now runs the real payload.js , tif_writer.js and site.js under a DOM shim. Against the unfixed file it prints buildState = "FAILED: tifBytesNan is not defined" and none enabled . Against the fixed file it prints verdict: PASS (20/20 steps) . Three fixes, not one. tifBytesNan is declared, and the optional NaN-nodata variant is built in
its own guarded function — a failure in the optional variant can no longer block the
required file . The built file is now deflate-compressed in the browser, so the download is ~107 KB instead of ~47 MB and matches the container shape the Python
pipeline writes ( rasterio compress="deflate" ). A finished .tif now ships in docs/downloads/ and is linked
from the top of this page, so a visitor with JavaScript disabled — or with a browser that
cannot run the builder — still has a file to submit. This is the pattern the sibling team
sites use. Covered by tests/test_site_build.py (16 tests) in both routes, and run for two browsers in each — one with CompressionStream and one without:
the browser build is read back with rasterio and compared to the shipped payload
bit-for-bit, and both files must pass gems.raster.check_submission — the same
gate that refuses a file the form would reject with "Predicted values must be in range [0, 1]" . Incident recorded as FLAG #14 in research/limitations_and_next.md . Why the team kept scoring 0.1563 — and what changes now Evidence check (2026-09-28/29). The published GEMSDOE1 and
